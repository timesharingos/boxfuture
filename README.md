# boxfuture

权责发生制个人记账工具：**未来义务提前锁定、双预算池、只追加不可改的账本**。

> 设计来源：`exprdocs/origin.txt`（原始草稿）与 `exprdocs/detail-design.md`（详细设计 + 决策记录）。
> 技术栈：Tauri 2 + React 18 + TypeScript + Tailwind 4 + Rust + SQLite（rusqlite bundled）。

---

## 它解决什么问题

普通记账软件记录「钱什么时候花出去」。这套系统记录「**承诺什么时候发生**」：

- 下单买期货，定金记当月，**尾款自动锁定未来那个月的预算**；
- 月末把规律预算的结余转成一次性预算，一次性预算**永不再生**；
- 每笔交易只追加，改错必须用冲销/核销/展期，**审计线索完整**；
- 消费按金额自动分级，中等以上**必须填写理由/时效/市场均价**，不填就存不进去；
- 未来 12 个月要准备多少钱、还能提前消费多少，一眼可见。

## 语言

界面支持中文 / English 切换：

- **默认跟随系统语言**：`navigator.language` 以 `zh` 开头用中文，否则用英文；
- 顶栏右上角的 `EN` / `中文` 按钮可随时切换，选择会记在 `localStorage`；
- 翻译字典在 `src/lib/i18n.tsx`，以**中文原文作 key**，新增文案时补一条即可。

## 常见构建问题

### `failed to run custom build command for libsqlite3-sys` / `cl : error D8050`

现象：

```
cl : 命令行 error D8050 : 无法执行 "…\c1.dll" : 未能将命令行放入调试记录中
error occurred in cc-rs: command did not execute successfully (status code exit code: 2)
```

原因：`rusqlite` 的 `bundled` 特性需要在构建时用 MSVC 编译 SQLite 的 C 源码。
当 `TMP` / `TEMP` 指向系统临时目录时，本机上 `cl.exe` 会报 D8050 而失败；把临时目录换到可写位置即可。

仓库已内置修复：`.cargo/config.toml` 把构建期的 `TMP` / `TEMP` 强制指向 `src-tauri/target/`
（该目录由 cargo 每次构建自动创建，`cargo clean` 后也不会缺失），
所以正常的 `npm run tauri:dev` 不需要额外操作。

如果仍然失败，可以：

1. 清理后重试：`cargo clean -p libsqlite3-sys`；
2. 用 `npm run dev:win` / `npm run build:win`，它会先加载 Visual Studio 的编译环境（`vcvars64`）再构建；
3. 确认已安装「使用 C++ 的桌面开发」工作负载与 Windows SDK，且 C 盘有足够空间。

## 运行

```bash
npm install
npm run tauri:dev      # 开发模式
npm run tauri:build    # 打包安装程序
```

前置：Node 22+、Rust stable、Visual Studio 2022 C++ 生成工具、WebView2。

数据文件：`%APPDATA%\boxfuture\boxfuture.db`，附件在 `%APPDATA%\boxfuture\attachments`。

数据目录按以下顺序解析，取第一个**可写**的：

1. 环境变量 `BOXFUTURE_DATA_DIR`
2. `%APPDATA%\boxfuture`
3. `%LOCALAPPDATA%\boxfuture`
4. 程序所在目录的 `data\`

如果降级到了 3 或 4（常见于受限/沙箱环境），界面顶部会出现橙色提示条并显示实际路径，避免数据悄悄写到别处。

**便携模式**：设置环境变量 `BOXFUTURE_DATA_DIR` 指向任意目录，数据库、附件与 WebView2 数据都会放在该目录下，适合放 U 盘或做测试隔离。

首次启动会创建三个示例账户（日常卡 / 储备卡 / 投资账户），可在「账户」页改名或归档。

## 功能（首版）

| 模块 | 说明 |
|---|---|
| 账户 | 逻辑账户 + 双资金池（规律 / 一次性），月度额度，归档 |
| 月结 | 自动结账并提示结转明细；可手动结账、重开上月 |
| 现货 | 即时现货与未来现货（全额预付但锁定未来月） |
| 期货 | 定金 + 尾款、**定金/尾款可分属不同账户与预算池**、多商品明细、额外费用、供应商、原币金额与汇率、附件、多次支付、核销、展期、取消 |
| 计提 | 估计金额占位，可无限期挂起，核销后生成真实现货交易 |
| 冲销 | 部分冲销、多次冲销、冲销金额可超过原交易（超出部分自动落为新支出） |
| 转账 | 账户间 / 池间划转，禁止「一次性 → 规律」 |
| 收入 | 规律收入 / 一次性收入，一次性收入只能进一次性预算 |
| 分级 | 刚需 / 小额 / 中等 / 大额 / 设备，硬性必填 + 小额月次数限制（超限自动升级） |
| 报表 | 利润表、现金流量表、预算执行、延迟类平摊表、预订习惯、超前消费能力 |
| 审计 | 任意交易的生命周期时间线、预算分录、现金流、关联事件 |

## 核心规则（实现口径）

1. **预算分录（posting）是唯一事实**：所有交易折算成 `(账户, 池, 月份, 金额)`，余额 = 额度 + 分录之和。
2. **未来锁定**：往未来月份写分录即可，不需要额外机制。
3. **月归一**：任何内部调整若目标月已结账，自动改记到当前月，历史投影永不改变。
4. **调整方向单向**（Q8 决策）：预算释放（退款/冲销）一律进一次性池；额外成本先扣一次性，不足再扣规律（规律可为负）。
5. **期货口径**：分级与计数器都按订单总金额判定；尾款只锁预算不计次数。
6. **尾款两段式**：先「核销」改预估金额并重算预算，再「支付」（可多次）只记现金流。
7. **分级硬阻断**：必填项缺失直接拒绝保存。
8. **月份结算视图**：仪表盘（规律/一次性余额、未来 12 月义务、待付义务、超前消费能力）全部按顶部所选月份结算；已结账月份使用真实结转分录，未结账月份按规律结余**模拟结转**后再汇总（即「如果现在结算到那个月」的结果）。
9. **额度改动次月生效**：在「预算」页修改规律额度时，所选月份的额度不变，新额度从**下个月**开始；同一生效月份重复修改会覆盖前一次。
10. **账户期初**：新建账户可同时填写初始规律预算与初始一次性预算（正数余额 / 负数欠款）。
11. **预算注入行**：账本里每个账户每月会显示一条只读的「规律预算注入」虚拟行（不落库、无现金影响、不计损益），点开可看该账户的额度变更历史；按月筛选/搜索时会自动隐藏。

## 工程结构

```
src/                     React 前端（零 SQL，全部通过 invoke）
  components/ui.tsx      基础组件与 toast
  features/              仪表盘 / 记一笔 / 账本 / 预算 / 未来 / 账户 / 报表 / 设置
  lib/                   IPC 封装、类型、格式化、react-query hooks
src-tauri/
  migrations/0001_init.sql
  src/domain.rs          Month / Pool / AppError
  src/db.rs              连接、迁移、种子数据
  src/engine/            记账内核（mod / write / close / read）
  src/reports.rs         六张报表的聚合
  src/commands.rs        Tauri 命令层（薄）
  tests/engine.rs        12 个引擎集成测试
```
